# linkedin-tyashin-next

Marketing website for **Tyashin for LinkedIn** (the product at linkedin.tyashin.com, owned by Aapastech Pvt Ltd; internal repo name LinkedIn Leader). AI that writes LinkedIn posts in the user's own voice, checks them, and publishes through LinkedIn's official API.

It runs on the Tyashin website platform as a per-project Next.js Worker (OpenNext on Cloudflare). Worker name: `site-linkedin-tyashin-next`.

This repo is the marketing site only. Sign-in and sign-up live in the product app; every CTA goes there through `src/lib/app-links.ts`.

## Stack

- Next 16 (App Router, RSC), React 19, `@opennextjs/cloudflare`
- Tailwind v3, tokens as `--brand-*` CSS variables (`src/app/layout.tsx`, `src/app/globals.css`)
- Fonts self-hosted with `next/font/local` (`src/fonts`, all OFL). No build-time network dependency.
- No analytics, chatbot, consent or error-reporting scripts in the layout: the platform injects those at the edge. No CSP that blocks inline scripts.

## Run it

```bash
nvm use 24          # Node >= 22
npm install
npm run dev         # http://localhost:3000

npx next build && npx next start -p 3311
node scripts/check-site.mjs http://localhost:3311   # routes, crawl, copy rules

npx @opennextjs/cloudflare build                    # Worker bundle in .open-next/
```

Never run `next build` while `next dev` is running (shared `.next`).

## Environment

Every variable is optional. With all of them unset the site builds and renders: the blog and legal pages use local fallbacks and the forms say plainly that they are not available yet.

| Variable | Used for | When unset |
|---|---|---|
| `TYASHIN_API_KEY` | Server-only project key: blog, legal, contact, newsletter, grievance | Local blog posts and legal text; forms show "not available yet" |
| `TYASHIN_API_URL` | Platform API base | `https://website-api.tyashin.com` |
| `PROJECT_ID` | Tyashin project id (kept for the deploy workflow and future calls) | empty |
| `NEXT_PUBLIC_SITE_DOMAIN` | Canonical host for canonicals, OG and JSON-LD | `linkedinautomation.tyashin.com` |
| `NEXT_PUBLIC_APP_URL` | Where `/signup/` and `/login/` live | `https://linkedin.tyashin.com` |
| `TYASHIN_SLUG_HOST` | `https://<slug>.sites.tyashin.com`, for workers.dev rewrites of platform-owned paths | no rewrites |
| `ROBOTS_NOINDEX` | `true` adds a noindex meta. Baked at **build** time for prerendered pages | indexable |

`NEXT_PUBLIC_*` and `ROBOTS_NOINDEX` are read at build time. Export them in the build environment, not only in `wrangler.jsonc`.

## Where things are

| Path | What |
|---|---|
| `src/config/site.ts` | Every brand string, nav and footer |
| `src/lib/app-links.ts` | The only place sign-up and sign-in URLs are defined |
| `src/lib/api.ts` | The only place the platform API is called |
| `src/lib/seo.ts` | `pageMetadata()`; every page's metadata goes through it |
| `src/lib/site-routes.ts` | `getSiteRoutes()`: one list for the sitemap, llms.txt and static params |
| `src/lib/knowledge-graph.ts` | One JSON-LD `@graph` per page |
| `src/lib/pricing.ts` | Static mirror of the product's price table |
| `src/lib/blog.ts`, `src/lib/legal.ts` | Platform first, local fallback second |
| `src/data/features.ts` | Feature inventory with `status: 'live' | 'soon'` |
| `src/data/roadmap.ts` | Everything that is not live |
| `src/components/ComingSoon.tsx` | The one Coming-soon badge and panel |
| `docs/CONTENT-SOURCES.md` | Which fact came from which file |

To move a feature from Coming soon to live: change its `status` in `src/data/features.ts`, remove it from `src/data/roadmap.ts`, and check the FAQ answers that mention it.

## Routes

Pages: `/`, `/how-it-works`, `/features`, `/use-cases`, `/use-cases/[slug]` (founders, consultants, executives, career-changers, b2b-sales, coaches, students), `/pricing`, `/safety`, `/roadmap`, `/faq`, `/blog`, `/blog/[slug]`, `/contact`, `/about`, `/privacy-policy`, `/terms-and-conditions`, `/sales-terms`, `/grievance`, plus a custom not-found.

Handlers: `/sitemap-pages.xml`, `/llms.txt`, `/api/contact`, `/api/newsletter`, `/api/grievance`, `/api/geo`.

Redirects: `/privacy`, `/terms`, and the old site's `/whats-coming`, `/automation`, `/compare` and the dropped comparison post.

There is no `app/sitemap.ts`: the platform owns `/sitemap.xml` and references `/sitemap-pages.xml` from its index.

## Blog

`/blog` and `/blog/[slug]` render per request. The platform Blog API is asked first. While it has no published posts (or no key is set), the six posts migrated from the previous site are served from `src/data/blog-posts.ts`. Once the platform has one published post, the local posts leave the index and the sitemap; their URLs keep resolving.

`src/data/blog-posts.ts` and `src/data/legal-fallback.ts` are generated by `scripts/migrate-blog.py` and `scripts/migrate-legal.py` from the product repo. Do not hand-edit them.

## Deploy

Do not write `.github/workflows/deploy.yml` by hand. After the GitHub repo exists (public, under `tyashin-sites`) and the first push is done, call the platform's adopt endpoint, which installs the canonical workflow and wires the project:

```bash
curl -X POST "https://website-api.tyashin.com/api/v1/github/$PROJECT_ID/adopt" \
  -H "Authorization: Bearer $JWT" -H "Content-Type: application/json" \
  -d '{"repoName":"linkedin-tyashin-next","workerScriptName":"site-linkedin-tyashin-next","installWorkflow":true,"overwriteWorkflow":true}'
```

A manual deploy, when needed: `npx @opennextjs/cloudflare build && npx @opennextjs/cloudflare deploy` (not `wrangler deploy`). After any `wrangler secret put`, deploy again, or the static assets go missing.

## Cutover checklist

Before the first deploy

- [x] Replace `REPLACE_WITH_KV_ID` in `wrangler.jsonc` with the `NEXT_INC_CACHE_KV` namespace id.
- [x] Create the GitHub repo as **public**, push, run `/adopt`.
- [ ] Set `TYASHIN_SLUG_HOST` once the project slug is known.
- [x] Domains (decided 2026-11-16): the app stays on `linkedin.tyashin.com` untouched (LinkedIn OAuth, Stripe and Razorpay return URLs unchanged). This site lives on its own host, `linkedinautomation.tyashin.com`. One host only: several keyword subdomains serving the same pages would be duplicate content and split ranking signals.

On the preview host

- [ ] Install and configure plugins: Contact Form, Newsletter, Blog, SEO Co-Pilot, analytics. Nothing customer-facing is on by default.
- [ ] Set blog ownership to `storefront` if `/adopt` did not (`PATCH /projects/<id>/tyashin-pages` with `blog-index` and `blog-post`). Check `/blog` shows this site's header and footer.
- [ ] Add the three legal pages in the platform with slugs `privacy-policy`, `terms-and-conditions`, `sales-terms`, or keep the local fallback.
- [ ] Submit the contact, newsletter and grievance forms once each and confirm they arrive.
- [ ] Keep "Serve /llms.txt" off in SEO Co-Pilot if this site's `/llms.txt` should be the one served.
- [ ] `node scripts/check-site.mjs <preview-url>` passes.

Going live

- [x] Build with `ROBOTS_NOINDEX=false` and set the same in `wrangler.jsonc`, then redeploy.
- [x] Set `NEXT_PUBLIC_SITE_DOMAIN` to the production host at build time.
- [ ] Verify the live `<head>` has no noindex: `node -e "fetch('https://<domain>/').then(r=>r.text()).then(t=>console.log(t.slice(0,t.indexOf('</head>')).match(/<meta[^>]*(robots|googlebot)[^>]*>/gi)))"` should print `null`.
- [ ] Confirm `x-tyashin-dispatch: nextjs` on the production host.
- [ ] Check the old site's URLs redirect: `/privacy`, `/terms`, `/whats-coming`, `/automation`, `/compare`.
- [ ] Add the site to `CUSTOMERS.md` and to `CUSTOMER_URLS` in the platform's `safe-deploy.sh`.

## Copy rules

- No other product is named anywhere in `src/`. The buyer's checklist replaces comparisons.
- No testimonials, logos, user counts or performance statistics.
- Company name only; no street address.
- "Monthly AI allowance", never tokens.
- Anything not live uses `ComingSoon` and is listed on `/roadmap`.

`scripts/check-site.mjs` enforces the first and third rules and the link rules.
